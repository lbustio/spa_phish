# SpaPhish: Companion Code for a Spanish Phishing Email Dataset

This repository provides the companion code for **SpaPhish**, a Spanish-language phishing email dataset distributed through Mendeley Data.

Dataset DOI: `10.17632/hz2d6gz7pc.4`

SpaPhish contains **1,395 anonymized emails** collected between **2014 and 2025**:

* **731 phishing emails**
* **664 legitimate emails**
* raw subject and body text
* technical metadata such as URLs, routing depth, and attachment statistics
* persuasion annotations based on the **Principles of Persuasion**
* human-written justifications for the persuasion labels

The dataset was anonymized with manual redaction and controlled substitution so that the content remains readable while reducing re-identification risk.

## Dataset at a Glance

SpaPhish combines three complementary layers:

* native Spanish phishing and legitimate email examples
* structured technical indicators extracted from email headers and content
* psychological annotations that support explainable analysis

SpaPhish is useful for:

* phishing detection experiments in Spanish
* hybrid text-plus-metadata modeling
* analysis of URLs, attachments, and routing patterns
* longitudinal studies of phishing tactics
* annotation reliability and persuasion research

## What This Repository Provides

The code in this repository lets you:

* process raw `.eml` files into a cleaned dataset
* analyze the structured CSV generated by `main.py process`, or any other equivalent structured SpaPhish CSV, to generate descriptive tables and figures
* generate publication-style HTML and PDF reports
* run the full pipeline from a single entry point, `main.py`

## Getting Started

### 1. Create the environment

If you use Conda:

```bash
conda env create -f environment.yml
conda activate spaphish
```

Run that command from the repository root so the Conda environment can read `requirements.txt` during setup.

If you prefer `venv`:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Provide your input data

Choose the input that matches the stage you want to run:

* If you want to build a SpaPhish-like dataset from scratch, place raw `.eml` files under `data/raw/`.
* If you already have a structured CSV from a previous run, point `analyze` or `all` to that file with `--csv`.
* If you want to reproduce the published SpaPhish-style outputs from the reference release, use the structured CSV generated from the raw email processing stage.

## Command-Line Interface

`main.py` is the only public entry point. It exposes four descriptive subcommands:

| Command | Purpose | Main Input | Main Output |
| --- | --- | --- | --- |
| `process` | Convert raw `.eml` files into the structured SpaPhish CSV | `data/raw/` | `output/processing/spaphish_eml_dataset.csv` |
| `analyze` | Generate tables and figures from the structured CSV produced by `process` | `output/processing/spaphish_eml_dataset.csv` | `output/tables/` and `output/figures/` |
| `report` | Build the HTML and PDF report artifacts from analysis outputs | `output/tables/` and `output/figures/` | `output/index_updated.html`, `output/SpaPhish_Report_UPDATED.pdf`, `output/SpaPhish_Report.pdf` |
| `all` | Run processing, analysis, and reporting in sequence | raw emails or an existing CSV | all outputs above |

### 3. Process raw emails only

```bash
python main.py process --raw-dir data/raw
```

This stage:

* hashes raw `.eml` files with SHA-256
* deduplicates messages
* extracts structural and textual features
* optionally runs OCR on embedded images when the OCR tools are available
* exports a cleaned CSV for downstream analysis

### 4. Analyze the structured CSV

```bash
python main.py analyze --csv output/processing/spaphish_eml_dataset.csv
```

This stage reads the structured CSV created by `main.py process` and generates the descriptive tables and figures under `output/tables/` and `output/figures/`.

If you already have a structured SpaPhish CSV from a previous run, you can point `--csv` to that file instead.

### 5. Build report artifacts

```bash
python main.py report --report-format both
```

This command reads the tables and figures already stored in `output/` and builds the publication-style report outputs.

The `html` report path also writes a companion PDF rendered from the HTML, while the `pdf` path builds the standalone PDF directly.

### 6. Run the full pipeline end to end

```bash
python main.py all --raw-dir data/raw --report-format both
```

You can also start `all` from an existing CSV:

```bash
python main.py all --csv "data/Spaphish dataset - DiB.csv" --report-format both
```

### Useful CLI options

* `--no-ocr`: disable OCR even if Tesseract is available
* `--ocr-lang`: set the OCR language, for example `eng+spa`
* `--max-images-per-email`: limit the number of images processed per email
* `--max-ocr-text-chars`: cap the amount of OCR text stored per email
* `--allow-remote-images`: allow remote image references while parsing HTML emails
* `--dataset-name`: change the dataset label used in schema outputs
* `--report-format`: choose `html`, `pdf`, or `both`

## Dataset Fields

The CSV is organized into three layers:

1. Raw message content
   * subject
   * body text
   * anonymized content
2. Technical indicators
   * URL counts and URL lists
   * routing depth from `Received` headers
   * attachment counts, file types, and sizes
3. Psychological annotations
   * binary persuasion labels for the five SpaPhish principles
   * annotator justifications

## Notes for Mendeley Data

This repository is intended to be linked from the SpaPhish Mendeley Data record as the companion code.

Typical workflow:

1. Place raw `.eml` files in `data/raw/` or provide an existing structured CSV.
2. Run `main.py process` to build the structured dataset from raw mail.
3. Run `main.py analyze` to generate tables and figures.
4. Run `main.py report` to build the report artifacts.

Because data files are excluded from version control, users can clone the repository and add their own local inputs before running the pipeline.
